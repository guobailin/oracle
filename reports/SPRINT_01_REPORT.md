# Sprint 1 — 甲骨文未释读现状与研究机会报告

项目：Oracle；执行日期：2026-11-11；覆盖T1.1–T1.4桌面研究初稿；状态：REVIEW。

## 1. 执行摘要

本轮完成未释读问题分类、核心数据库盘点、公开数据集盘点和代表性文献梳理。最重要结论：甲骨文AI研究已有成熟基础设施和端到端尝试，Oracle 应避免重复做通用OCR/数据库，而应聚焦未知类、长尾和疑难释读的独立评测，以及可审计证据链。

三个关键现实：
1. 未释读包含未识别字形、字形归属争议、残损不确定、已识字形但词义/用法争议、整句解释争议和碎片缀合。
2. 数据资源统计单位不同：字头、字形、图像、字符实例、缺字位置、句子单元不可混为一谈。
3. 数据可见不代表可下载、训练或再分发。HUST-OBC非商业许可、OBIMD数据卡片许可、机构数据库访问条件及第三方图像权利必须分别审查。

## 2. 关键数据与平台

| 资源 | 已知规模/功能 | 对 Oracle 的意义 |
|---|---|---|
| 小學堂甲骨文数据库 | 2,548字头、24,701字形（2026-11-11） | 字形索引和学术检索；不是全部出土字类普查 |
| 傅斯年图书馆甲骨拓片库 | 馆藏超40,000拓片；21,556笔数字记录可检索 | 原始拓片与馆藏/考古记录线索 |
| 殷墟甲骨文数据库 | 图像、摹写、释文对应；支持甲骨号、释文和字形检索 | 重要辞例资源，但机构访问/购买条件需核实 |
| 殷契文渊 | 字形库、著录库、文献库、知识服务及AI辅助工具 | 直接竞争/合作平台，需先做差异分析 |
| HUST-OBC | 140,053图像；已释读与未释读类别分开 | 视觉识别、开放集、长尾和数据泄漏研究 |
| OBIMD | 10,077图像、93,652字符、21,667缺字、21,941句子单元 | 上下文、缺字恢复、图像与辞例联合评测 |
| AlphaOracle | 形态分析、语境检索、训诂验证的多阶段系统 | 必须对标的端到端辅助释读系统 |

**口径警告：** 小學堂的2,548是字头数、24,701是字形数；HUST-OBC的9,411是数据集标注未释读类别数；OBIMD的93,652是标注字符数。它们不是同一种统计单位，不可相加或直接换算为“还有多少甲骨文未破译”。

## 3. 现状判断

已有基础：字头/字形检索、拓片目录、图文对照、部分跨库关联；已释读字形识别与检索；大规模字符图像和多模态辞例数据；形体—语境—训诂辅助释读流程。

研究空间：未知类拒识；按实物/著录来源隔离数据；残损字形与异体近形字证据分层；候选可回溯原始出处、辞例和学术文献；专家盲测与可复现评价；评估AI是否改善真实研究过程。

## 4. 推荐定位

核心问题：对于罕见、未知或残损的甲骨文字形，AI能否在不强行给出释读的前提下，提供可复现、可审计、可被专家反驳或确认的证据链，并在严格跨材料盲测中证明有效性？

优先研究：未知类与长尾处理；视觉候选与辞例语境证据分层检索；专家盲评下的证据质量、弃答能力和实际效率。暂不建议从头训练大型视觉语言模型，也不建议先建设全量新数据库。

## 5. 风险与约束

- 学术风险：分类和结论须由甲骨学专家校订。
- 数据风险：公开页面不等于允许批量采集；许可需落实到数据集、原图和第三方馆藏。
- 评估风险：随机图像切分可能造成同一实物/字形跨集合泄漏；优先按材料来源隔离。
- 模型风险：模型可能幻觉笔画、过度解释；必须允许弃答并展示反证。
- 复现风险：论文公开结果不能替代独立复现。
